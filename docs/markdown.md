# Правила оформления Markdown

## 1. Назначение

Этот раздел устанавливает единые правила форматирования файлов Markdown в проекте Design of an AI-Powered Information System.

Соблюдение правил позволяет поддерживать единый внешний вид документации и упрощает автоматическую проверку файлов.

## 2. Кодировка и расширение файлов

Документы должны сохраняться в кодировке UTF-8 и использовать расширение `.md`.

Названия файлов должны быть понятными и отражать содержание документа. Рекомендуется использовать латиницу, нижний регистр и дефисы между словами.

Примеры:

- `technical-content.md`;
- `model-description.md`;
- `deployment-guide.md`.

Не рекомендуется использовать пробелы, случайные сокращения и несколько вариантов написания одного и того же имени.

## 3. Заголовки

Для заголовков используется символ `#` с пробелом после него.

```markdown
# Название документа

## Основной раздел

### Подраздел
```

Необходимо соблюдать иерархию заголовков и не использовать жирный текст вместо заголовка.

## 4. Абзацы и переносы строк

Разные абзацы разделяются пустой строкой.

```markdown
Это первый абзац.

Это второй абзац.
```

Не следует использовать большое количество пустых строк для визуального оформления.

## 5. Выделение текста

Для выделения важных слов и фраз используется жирный текст:

```markdown
**Обязательное требование**
```

Курсив применяется для умеренного акцента или обозначения термина при первом упоминании:

```markdown
*Инференс* — применение обученной модели к новым данным.
```

Не рекомендуется использовать форматирование без смысловой необходимости.

## 6. Списки

Маркированные списки оформляются с помощью дефиса:

```markdown
- Первый элемент.
- Второй элемент.
- Третий элемент.
```

Для последовательных действий применяется нумерованный список:

```markdown
1. Установить зависимости.
2. Настроить окружение.
3. Запустить приложение.
```

В пределах одного списка необходимо придерживаться единого оформления элементов и вложенности.

## 7. Ссылки

Для внешних ссылок используется синтаксис:

```markdown
[Официальная документация Python](https://docs.python.org/3/)
```

Для внутренних ссылок следует использовать относительные пути:

```markdown
[Техническое содержание](technical-content.md)
```

Название ссылки должно сообщать, куда она ведёт. Перед публикацией необходимо проверить работоспособность ссылок.

## 8. Изображения

Изображения добавляются с альтернативным текстом:

```markdown
![Схема взаимодействия компонентов](images/component-architecture.png)
```

Альтернативный текст должен передавать назначение изображения. Для сложных схем необходимо добавить текстовое объяснение в основном содержании документа.

## 9. Блоки кода

Для коротких фрагментов используется обратный апостроф:

```markdown
Параметр `PORT` задаёт порт приложения.
```

Для многострочного кода используются ограждения из трёх обратных апострофов с указанием языка:

````markdown
```python
print("Hello, world!")
```
````

Примеры команд оболочки оформляются с указанием подходящего языка, например `bash`, `powershell` или `text`.

Код должен сохранять отступы и быть пригодным для копирования. Секреты и реальные учётные данные запрещено помещать в примеры.

## 10. Таблицы

Таблицы должны иметь заголовки столбцов и использоваться для структурированных сравнений или справочных данных.

```markdown
| Параметр | Описание |
|---|---|
| `PORT` | Порт приложения |
| `LOG_LEVEL` | Уровень журналирования |
```

Не следует размещать в таблицах длинные инструкции, которые трудно читать на узких экранах.

## 11. Цитаты и предупреждения

Для цитат используется символ `>`:

```markdown
> Важно: перед публикацией проверьте актуальность конфигурации.
```

Если проект использует специальные блоки предупреждений MkDocs Material, их синтаксис должен соответствовать настройкам темы и расширений проекта.

## 12. Единообразие форматирования

В пределах проекта необходимо соблюдать единый стиль заголовков, списков, ссылок и блоков кода.

Автоматические проверки Markdown следует выполнять с помощью настроенного линтера. Конкретные правила линтера определяются конфигурацией репозитория.

## 13. Проверка перед публикацией

- [ ] Файл сохранён в UTF-8 с расширением `.md`.
- [ ] Заголовки оформлены корректно.
- [ ] Списки имеют единый стиль.
- [ ] Ссылки и изображения доступны.
- [ ] Блоки кода содержат правильное обозначение языка.
- [ ] В примерах отсутствуют секретные данные.
- [ ] Markdown проходит автоматическую проверку.
