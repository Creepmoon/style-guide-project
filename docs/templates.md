# Шаблоны технической документации

## 1. Назначение

Этот раздел содержит рекомендуемые шаблоны для создания документов проекта Design of an AI-Powered Information System.

Шаблоны помогают сохранять единообразную структуру документации и не пропускать важные сведения. Не все разделы обязательны для каждого типа документа: ненужные пункты допускается удалять, если это не снижает полноту описания.

## 2. Шаблон README

README предназначен для краткого знакомства с проектом и получения основных инструкций по его запуску.

```markdown
# Название проекта

## Описание

Краткое описание назначения проекта и решаемой задачи.

## Основные возможности

- Возможность 1.
- Возможность 2.
- Возможность 3.

## Технологический стек

Перечень основных технологий и инструментов.

## Требования

- Необходимая версия среды выполнения.
- Необходимые инструменты и сервисы.

## Установка

Инструкция по получению исходного кода и установке зависимостей.

## Конфигурация

Описание необходимых переменных окружения и параметров.

## Запуск

Команды для запуска приложения.

## Проверка

Инструкция по запуску тестов или выполнению проверок.

## Структура проекта

Краткое описание основных каталогов.

## Ограничения

Известные ограничения и особенности использования.

## Лицензия и контакты

Информация указывается при необходимости.
```

Инструкции должны быть проверены на актуальной версии проекта.

## 3. Шаблон описания технического компонента

Используется для документирования сервиса, модуля или другого самостоятельного компонента.

```markdown
# Название компонента

## Назначение

Какую задачу решает компонент.

## Ответственность

Какие функции входят в его область ответственности.

## Входные данные

Какие данные получает компонент и в каком формате.

## Результат

Какие данные или действия формирует компонент.

## Взаимодействие

С какими компонентами взаимодействует и через какие интерфейсы.

## Конфигурация

Необходимые параметры настройки.

## Ошибки и ограничения

Возможные ошибки, ограничения и особые условия.

## Запуск и проверка

Как запустить компонент и проверить его работу.

## Связанные материалы

Ссылки на API, схемы, инструкции и другие документы.
```

## 4. Шаблон описания API

```markdown
# Название API или операции

## Назначение

Описание задачи, решаемой операцией.

## Endpoint

HTTP-метод и путь.

## Авторизация

Требования к аутентификации и авторизации.

## Параметры

Описание параметров пути и строки запроса.

## Тело запроса

Формат и пример тела запроса, если оно используется.

## Успешный ответ

Формат, код ответа и пример результата.

## Ошибки

Возможные коды ошибок и условия их возникновения.

## Ограничения

Ограничения использования, если они существуют.
```

Фактические названия полей, типы данных и коды ответов должны соответствовать реализации API.

## 5. Шаблон описания модели машинного обучения

```markdown
# Название модели

## Назначение

Описание решаемой задачи и предполагаемого использования модели.

## Данные

Источник, характеристики и ограничения набора данных.

## Предварительная обработка

Этапы подготовки входных данных.

## Архитектура или алгоритм

Описание выбранного подхода.

## Обучение

Параметры обучения, разделение данных и используемые инструменты.

## Оценка качества

Метрики, условия эксперимента и полученные результаты.

## Использование модели

Требования к входным данным и формат выходных результатов.

## Ограничения

Известные ограничения и сценарии, в которых модель может работать некорректно.

## Воспроизводимость

Версии зависимостей, конфигурация эксперимента и необходимые артефакты.
```

Результаты оценки должны сопровождаться описанием методики. Если разделы не применимы к конкретной модели, это следует пояснить либо исключить их.

## 6. Шаблон инструкции

```markdown
# Название инструкции

## Цель

Какой результат должен получить читатель.

## Предварительные условия

Необходимые инструменты, права доступа и настройки.

## Порядок действий

1. Первое действие.
2. Второе действие.
3. Третье действие.

## Ожидаемый результат

Как определить, что процедура завершилась успешно.

## Возможные ошибки

Типичные проблемы и способы их устранения.

## Связанные материалы

Ссылки на дополнительные инструкции.
```

Инструкции должны содержать выполнимые шаги и проверяемые результаты.

## 7. Шаблон записи об архитектурном решении

Для важных архитектурных решений рекомендуется использовать отдельную запись.

```markdown
# ADR-NNN: Название решения

## Статус

Предложено / Принято / Отклонено / Заменено.

## Контекст

Проблема и обстоятельства, требующие решения.

## Рассмотренные варианты

Перечень возможных подходов.

## Решение

Выбранный вариант и его обоснование.

## Последствия

Преимущества, ограничения и последствия для системы.
```

Нумерация записей должна быть последовательной. Принятое решение необходимо обновлять или заменять новой записью при существенном изменении обстоятельств.

## 8. Правила применения шаблонов

- Используйте шаблон, соответствующий назначению документа.
- Сохраняйте обязательные разделы выбранного шаблона.
- Удаляйте неприменимые разделы или явно указывайте, что соответствующая информация отсутствует.
- Заменяйте все поясняющие заглушки фактическими сведениями.
- Проверяйте ссылки, примеры и конфигурацию перед публикацией.

Шаблон задаёт структуру, но не заменяет проверку достоверности и полноты содержания.
