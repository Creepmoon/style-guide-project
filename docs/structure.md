# Правила структурирования документации

## 1. Назначение

Этот раздел определяет правила организации технических документов проекта Design of an AI-Powered Information System. Правильная структура помогает читателю быстро находить информацию, понимать назначение документа и последовательно изучать материал.

## 2. Общие требования

Каждый документ должен иметь понятную цель и логичную структуру.

При создании документа необходимо:

- размещать наиболее важную информацию в начале;
- группировать связанные сведения в общих разделах;
- соблюдать логическую последовательность изложения;
- избегать чрезмерно длинных разделов;
- не дублировать большие фрагменты информации без необходимости;
- использовать ссылки на другие документы, если подробное объяснение уже существует.

Структура должна соответствовать назначению документа. Не требуется использовать все возможные разделы, если они не нужны для раскрытия темы.

## 3. Заголовки

Заголовки оформляются с помощью синтаксиса Markdown.

Пример:

```markdown
# Название документа

## Основной раздел

### Подраздел
```

Правила использования заголовков:

- заголовок первого уровня `#` используется для названия документа;
- заголовок второго уровня `##` обозначает основные разделы;
- заголовок третьего уровня `###` применяется для подразделов;
- последующие уровни используются только при реальной необходимости;
- уровни заголовков не должны пропускаться без причины;
- заголовки должны кратко отражать содержание раздела.

Не рекомендуется использовать заголовки исключительно для визуального выделения текста. Для этого следует применять стандартное форматирование Markdown.

## 4. Рекомендуемая структура документа

Для большинства текстовых документов рекомендуется следующая последовательность:

1. Название.
2. Назначение и краткое описание.
3. Область применения или предпосылки.
4. Основное содержание.
5. Примеры, инструкции или ограничения.
6. Связанные материалы и источники, если они необходимы.

Конкретный порядок может изменяться в зависимости от типа документа.

Например, инструкция по установке должна начинаться с требований и предварительных условий, а описание архитектуры — с назначения системы и её основных компонентов.

## 5. Абзацы и списки

Каждый абзац должен раскрывать одну основную мысль. Слишком длинные абзацы следует разделять на несколько логических частей.

Маркированные списки используются для перечисления независимых элементов. Нумерованные списки применяются для последовательных действий или шагов алгоритма.

Пример последовательности действий:

1. Установить зависимости.
2. Настроить переменные окружения.
3. Запустить приложение.
4. Проверить результат.

Если порядок выполнения не имеет значения, следует использовать маркированный список.

## 6. Таблицы

Таблицы подходят для сравнения параметров, перечисления конфигурационных значений и представления кратких справочных сведений.

Таблица должна иметь заголовки столбцов. Не следует использовать её для размещения больших текстовых блоков или сложных инструкций.

Пример:

| Параметр | Назначение |
|---|---|
| `PORT` | Порт приложения |
| `DATABASE_URL` | Строка подключения к базе данных |
| `LOG_LEVEL` | Уровень журналирования |

## 7. Ссылки между разделами

Если для понимания материала требуется информация из другого раздела, необходимо добавить внутреннюю ссылку.

Названия ссылок должны описывать назначение целевого документа. Не рекомендуется использовать формулировки «здесь» или «по этой ссылке» без дополнительного контекста.

При изменении структуры проекта необходимо проверять работоспособность внутренних ссылок.

## 8. Принцип достаточности

Документ должен содержать достаточно информации для понимания своей темы, но не должен включать сведения, не относящиеся к его назначению.

Если раздел становится слишком объёмным, рекомендуется разделить материал на несколько самостоятельных документов и связать их ссылками.

## 9. Проверка структуры

Перед публикацией документа необходимо убедиться, что:

- [ ] Название соответствует содержанию.
- [ ] Основные разделы расположены логично.
- [ ] Заголовки имеют правильную иерархию.
- [ ] Списки используются по назначению.
- [ ] Таблицы читаемы и имеют заголовки.
- [ ] Внутренние ссылки ведут к существующим документам.
- [ ] Отсутствуют необоснованные повторы.
